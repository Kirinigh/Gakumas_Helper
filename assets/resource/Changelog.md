## `v0.2.2` 竞技场公开预览版

这是 Gakumas Helper 本次 MaaGakumasu Windows x86_64 完整派生预览包，包含竞技场编成读取、离线计分、保守胜率选敌、挑战结果记录和配套识别资源。

**发布状态：预发布（prerelease）。** 本版本仍用于竞技场跨窗口和独立盲测收口，不代表稳定版验收已经完成；MFA Stable 通道不会自动收到本预发布。

### 相对上一公开预览版 `v0.2.1`：竞技场修复

- 重读己方编成时，先从当前游戏画面识别并记录 Grade，再读取九名成员；新鲜读取值会覆盖界面手选值。手选 Grade 只在不重读己方、复用既有缓存时用于纠错，不再污染新鲜读取。
- 每日挑战缺少前置准备标记时，允许在同一个准备函数内执行一次任务局部兜底；没有修改点击、滑动、详情、Provider、模拟、选敌或挑战动作链。
- 强化徽标新增严格的单正反色配对分支：只有三个独立源帧的描述符与几何一致、合法数字均为 `1`，且跨静区取得足够投票并包含一组完整正反色配对时才可采用；其他矛盾仍失败关闭。
- 徽标中心数字通道现在要求图块至少横向重叠两列，排除仅以一列擦过中心边界的卡面伪影，不放宽数字、像素或时间稳定性门槛。
- 为 ID 317“はじめてのラムネ+”的好调倍率强化补充完整领域特定语言（Domain-Specific Language，DSL）详情正证据：基础分、倍率和好调比例必须在同一原子光学字符识别（Optical Character Recognition，OCR）视图中完整一致，缺字段、跨视图拼接或目录结构不纯仍判为未知。该分支已通过离线匹配器回归；本次实机日志没有持久化对应卡身份，因此不把它记作 ID 317 的独立实机命中。

### `v0.2.2` 无挑战实机验证

一次完整只读 JJC 流程按 `Grade 7 → 己方 9 人 → 最终对手 27 人 → 各对手 2000 次模拟` 闭合；门槛设为 `100%`，没有选择对手或发起挑战，开发摘要记录为严格业务终态（strict closed）。此前发生阻断的第三队第一舞台第三人位置本轮未再失败，但因最终日志未保留该位置的卡身份，不能据此宣称特定卡已通过实机留出。最终接受轮的 `118` 次技能卡详情事务 P50/P95 为 `1.312/1.945` 秒，接受轮没有 UI 动作重试。

读取提供器（Provider）第一次尝试在卡 709 详情关闭后检测到源画面代际不稳定，按既有两次上限完整重读一次后闭合。该恢复只增加本轮节拍，没有放宽身份、详情关闭、源代际或挑战安全门。另有己方 `4` 次按未强化、对手 `6` 次按已强化的费用歧义兜底，均按既定胜率向下策略定位记录且没有中止流程；它们不代表已完成真实挑战或稳定版验收。

### 继承自 `v0.2.0` 的更新器边界

- 完整包不再声明上游 `MaaGakumasu` 的 MirrorChyan 资源身份。MFA 资源检查在没有派生版 MirrorChyan RID 时会回落到本项目 `interface.json.github` 指向的 GitHub Releases，不再把上游 `v1.4.9` 公告或完整包识别为 Gakumas Helper 更新。
- 该兼容修复只覆盖 MFA Core 中资源检查与资源更新的两个来源选择点；本地包更新、下载、文件事务和重启语义保持原样，不新增第二套更新器。
- GitHub Release 正文继续作为 MFA 远端“更新一览”；同一份发布说明正文由公开快照构建器渲染为包内 `resource/Changelog.md`，不再携带上游 `v1.4.9` 公告。
- 本次完整包版本为 `v0.2.2`；上游 Maa 版本继续只作为来源元数据记录。

### 继承自 `v0.2.0` 的竞技场基线

- Grade 随己方编成缓存复用；每日胜率模式可选择“未识别、7～1”，任务说明会显示最终采用的 Grade、来源，以及九名成员模拟样本的整数算术平均值。缓存有效时不会为这些字段完整重读己方。
- 加固零强化、多视图动态效果和强化次数证据。既有费用二态兜底仍只允许固定目录严格限定的单比特状态：己方按未强化、对手按已强化，并逐卡记录精确位置；其他身份、次数或效果矛盾继续失败关闭。
- 技能卡详情可在严格绑定同一卡位、两张新鲜详情帧、精确标题、完整强化语义和关闭后源卡内容后，安全覆盖卡图近邻结果完成消歧；成功只记为识别信息，不算错误或猜测兜底。
- 动态效果的多个 OCR 视图保持原子边界。单个截断或污染视图不会删除 full/native 的一致次数证据；有效视图互相冲突时仍会停止。
- 竞技场卡面粗参考的“图库、manifest、`hard_negative_evaluation.json`”三件套新增 1 个经独立详情标题和完整效果绑定的 ID 529 实机开发域原型；ID 559 的 14 条权威目录变体（2 份唯一图像字节）全部作为硬负门且 14/14 未翻转。529 的独立实机正例留出仍为 `PENDING`，详情标题覆盖继续只作严格绑定后的纵深防御。
- 兼容缓存路径显式禁止意外触发新的己方画面读取；仅模拟引擎 revision 变化时直接使用缓存编成重新模拟。
- 对手首次完整读取失败、第二次成功时，结构化日志会保留首次尝试的异常类型、错误码和详情；这不改变既有两次上限、整轮重读或挑战动作。
- 挑战结果已记录但回场尚未验证时会保留 pending 并阻止下一次挑战；开发摘要现在也会正确保留空数组和严格业务终态。
- 竞技场费用参考和 P 道具参考分别携带“数值制品、manifest、`production_handoff_evaluation.json`”三件套；Release 会重新计算容器、来源、目录与业务语义，不能只凭手写 `READY` 放行。P 道具还绑定独立冻结的 production 来源证据，Release 会从发布源码树重新加载并比较来源投影。
- 内置 RIS 引擎采用第二代可复算交接输出：67 项 RIS 来源负载由固定源码归档重建，Node.js、许可证、runner 和 scoring 共 4 项由已验证宿主基线复用或生成；Release 同时核对 canonical manifest、成功 production deployment、首父回滚点、协议和实际期数目录。旧的仅含 `READY` 状态输出会被拒绝。

### `v0.2.0` 基线实机验证范围

以下结果来自上一版 `v0.2.0` 的发布基线，不冒充本次补丁的新实机证明：发布前识别候选完成 3 次真实 JJC，均严格闭合结果和回场，赛果为 2 胜 1 负、舞台 5 胜 4 负；三轮均复用己方缓存且没有己方重读，费用二态兜底为 `0／2／0`。第二轮发生一次产品内部完整 Provider 重读，最终快照与挑战输入已证明隔离；首次异常现已改为结构化保留，但该现象仍属于节拍／可用性限制。后续接入的 ID 529 卡面图库已通过离线硬负门，尚不能借这三轮冒充独立实机留出。

### `v0.2.0` 基线已验证的节拍改善

详情标题目录改用等价索引，关闭动作复用已接受详情帧尺寸，源页恢复复用冻结六区签名。在相同候选环境的一队只读实机 A/B 中，42 次技能卡详情的总时长由 `65.198` 秒降至 `57.509` 秒，平均每次由 `1.552` 秒降至 `1.369` 秒；P50 由 `1.513` 秒降至 `1.327` 秒，P95 由 `2.004` 秒降至 `1.700` 秒，分别改善约 `11.8%`、`12.3%` 和 `15.2%`。OCR 证据、点击次数和判定阈值均未减少。该数据只证明详情读取主阶段；因两轮入口状态不同，不把完整任务墙钟差异计作本版本收益。

### 安装与更新

- 首次安装时下载 `MaaGakumasu-win-x86_64-v0.2.2.zip`，按需核对 checksums，解压到新的独立目录，并运行版本内 `deployment\Start-MaaGakumasu-Admin.cmd`。
- GKH 版本为 `v0.2.2`；对应的上游 Maa 标签在 Release manifest 与来源记录中单独固定。
- 从旧 `vMAJOR.MINOR.PATCH+gkh.*` 命名空间迁移时须手动安装本版本一次，并把 MFA 资源更新通道保持为默认 Stable。不要切换到 Beta 或 Alpha：在旧组合 Release 完成通道隔离前，这两个通道会把数值更高的旧版本误判为更新。Stable 看不到 prerelease，因此后续预览版本仍须手动安装。

### 使用入口

- 首次先添加并运行“重算竞技场己方总分”；成功后再运行“竞技场胜率分析并挑战（单次）”或“每日挑战 → 胜率选敌”。
- 默认门槛为三对手家族校正后的单侧 95% Wilson 下限达到 70%，模拟 2000 次，模拟超时 180 秒。
- 完整步骤、缓存边界和故障处理见仓库[指导中心](https://github.com/Kirinigh/Gakumas_Helper/blob/main/guides/README.md)。

### 预览边界

- 本包可供试用，不代表竞技场全部跨窗口、盲测或更大分辨率验收已经完成。
- 无法唯一确认身份、页面、字段、赛季或结果时会失败关闭，不会用低可信结果继续挑战。
- 当前竞技场已测范围为 Windows 11 + DMM PC，最低竖向截图短边 720；540×960 不支持。
- 本包不声明上游 `MaaGakumasu` 的 MirrorChyan 资源身份，普通客户端更新只解析本项目 GitHub Releases。内置 pip 入口仍只更新 `requirements.txt` 中的 Python 依赖；模型、图库和 UI 不独立热更新，而是随完整派生包由 MFA 原生入口统一应用。竞技场 RIS engine/data 仍是唯一窄更新通道，只按最新成功 production SHA 成对更新，不构成第二套客户端更新器。
