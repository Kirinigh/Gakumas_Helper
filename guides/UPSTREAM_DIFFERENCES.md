# 与上游 MaaGakumasu 的区别

本项目以 Release manifest 中记录的固定 MaaGakumasu 上游版本为完整 Windows 包基线，并在同一个 Maa/MFA 客户端中加入竞技场能力。它不是第二套客户端，也不是在线模拟网站的包装器。

## 用户界面差异

| 项目 | 当前固定上游 MaaGakumasu 基线 | Gakumas Helper 预览版 |
| --- | --- | --- |
| 顶层任务 | 9 个 | 保留上游任务，新增 2 个默认关闭的竞技场入口 |
| 每日挑战默认 | 自动选敌 | 默认“胜率选敌”，仍保留全部上游模式 |
| 竞技场期数 | 无固定模拟目录选择 | “目录最新”或人工选择第 1～50 期 |
| 己方分数 | 不读取完整编成、不做本地分布缓存 | 独立重算、可读摘要、日常缓存复用 |
| 选敌依据 | 位置或综合力差等既有策略 | 完整编成模拟、20% 奖励、三局两胜和家族校正下限 |
| 调试采集 | 上游调试目录与导出方式 | 竞技场额外提供默认关闭的本地采集档位与配额 |

新增顶层任务是：

- “竞技场胜率分析并挑战（单次）”；
- “重算竞技场己方总分”。

新增配置包括竞技场期数、胜率门槛/模拟次数/超时、己方重算参数、自动重算开关和竞技场本地采集。它们只作用于派生竞技场路线。

## 内部新增能力

- 技能卡使用 64×64、128 维向量嵌入 (Vector embedding) 做 Top-5 余弦近邻检索；竞技场中的准确业务 ID、强化状态和具体自定义 ID 仍由固定目录与详情证据闭合。
- P 道具使用三帧完整性、最小分辨率门、64×64 归一化、固定图库 Top-24 粗排/多尺寸精排、前 12 接受守门及完整图库回退。128 维 P 道具嵌入只保留为离线诊断，不负责生产裁决。
- 自定义强化徽标只负责判断是否存在强化；具体强化 ID 通过有界详情点击解析。卡框或其他绿色卡面内容不能单独触发强化。
- 识别、模拟和点击共享同一份结构化成员观测；不完整成员不会形成部分队伍输入。
- 本地模拟器、阶段目录、模型、图库和规则数据都有版本清单与兼容约束。

这些识别能力是竞技场流程的内部实现，不作为独立用户开关暴露。

## 安全与发布差异

- 对实际输入进程执行管理员权限门；权限不明或不匹配时不开始挑战。
- 点击前记录唯一待决挑战；结果页必须完整闭合总体胜负、三场比分和奖励关系。
- 公开源码由允许清单生成独立单提交快照，不包含开发仓库历史、内部任务资料或本机运行态。
- Release 同时发布 manifest 与 checksums；包内带第三方许可证和资源来源说明。
- 用户配置、日志、缓存、截图、对局记录、私有训练数据和凭据不进入公开包。

## 保留的上游能力

启动、领取、社团、安排工作、商店、自动培育、支援卡识别以及上游原竞技场模式仍来自 MaaGakumasu。它们能在同一固定版本的未修改上游包复现的问题应优先反馈到[上游仓库](https://github.com/SuperWaterGod/MaaGakumasu/issues)。

派生包包含这些上游功能不等于本项目重新完成了所有平台和功能验收。上游的 macOS/Linux、模拟器、MirrorChyan、自动培育和 YOLO 使用说明仍以上游文档为准；当前派生竞技场预览仅声明 Windows 11 + DMM PC 的已测范围。

## 尚未宣称完成

- 竞技场识别的全部跨窗口、独立盲测和更大分辨率正式验收；
- 540×960 或更低画面支持；
- Gakumas Helper 专用 MirrorChyan 派生发布；包内若显示上游 `MaaGakumasu` 入口，它不是本项目更新通道；
- 模型/图库独立热更新；
- 自动更新成功、下载失败、兼容失败、校验失败和回滚的完整发布演练；
- 开发中的培育高分策略或其他未出现在当前公开 UI 的功能。

公开预览可供试用，但不能据此推断上述事项已经成为稳定产品能力。
