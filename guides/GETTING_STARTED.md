# 首次使用

## 适用范围

当前公开包面向 Windows x86_64 与 DMM 版游戏窗口，以非预发布版本发布并设为 GitHub Latest。上游 MaaGakumasu 的其他平台和模拟器能力仍属于上游范围；本派生版的竞技场新增能力尚未宣称完成这些环境的等价验证。

日常建议把游戏画面设为 `720×1280` 或更高的竖向 `9:16` 分辨率。识别门检查的是 MaaFramework 返回的图像：短边至少 `720` 像素，长边允许整数缩放带来的 1 像素舍入；它不等同于游戏设置中的物理窗口尺寸。物理 `540×960` 窗口已有读取验证，但完整日常流程尚未通过验收。

## 下载与安装

1. 首次安装或从旧组合版本迁移时，打开 [GitHub Releases](https://github.com/Kirinigh/Gakumas_Helper/releases)，下载标为 Latest 的 Windows x86_64 完整 ZIP。已使用独立 GKH 版本时，保持 MFA 默认 Stable，通过内置 GitHub 资源更新检查完整包；更新入口不可用时再手动下载安装。
2. Release 同时提供 checksums。需要人工复核首次下载时，可在 PowerShell 中核对 SHA-256：

   ```powershell
   Get-FileHash "MaaGakumasu-win-x86_64-vXXX.zip" -Algorithm SHA256
   ```

   请把 `vXXX` 替换为实际下载资产中的完整版本号。

3. 手动安装时将 ZIP 解压到一个新的目录。不要把单个文件手工覆盖进上游 Maa、其他派生版或旧版 Gakumas Helper；日常完整包更新使用 MFA 内置入口。
4. 运行版本内 `deployment\Start-MaaGakumasu-Admin.cmd`，通过管理员入口启动 Maa。该入口会为 Maa/Agent 子进程设置唯一且初始为空的 TEMP/TMP；直接双击 `MaaGakumasu.exe` 会绕过这项运行环境隔离。非管理员输入端不能控制管理员游戏窗口，程序会在开始任务或挑战前停止。
5. 在 Maa 中按上游方式连接游戏。程序只通过截图、图像识别、光学字符识别 (Optical Character Recognition, OCR) 和正常界面输入工作，不读取游戏进程内存，也不处理 DMM 账号密码。

DMM 用户首次打开时先把控制器从默认“模拟器”改为“PC”，再把资源切换为“DMM”。切换前 MFA 可能针对默认模拟器执行一次连接探针，并在没有 Android 调试桥 (Android Debug Bridge, ADB) 序列号时记录空地址诊断；这不表示“一键日常”业务任务已经执行，也不会连接 DMM 游戏。

## 第一次竞技场运行

1. 确认游戏已登录并停在可进入 `コンテスト` 的主界面，关闭遮挡弹窗。
2. 在 Maa 任务列表中添加“重算竞技场己方总分”。它默认不进入一键预设。
3. 竞技场期数默认选择“目录最新”。如果游戏当前期数与目录默认不一致，请人工选择正确期数；不存在或三个舞台数据不完整时流程会停止。
4. 保持默认 `2000` 次模拟与 `300` 秒模拟超时，单独运行己方重算。它会进入 `リハーサル`，读取三个舞台的当前编成并生成本机缓存，不会发起挑战。
5. 任务成功后，切换到其他任务再返回设置页，核对期数、三个舞台 ID、支援加成、有效 Grade 及来源、九名成员的整数模拟平均值和模拟次数。没有有效缓存的项目显示“未识别”。
6. 添加“竞技场胜率分析并挑战（单次）”。此任务会读取并完整模拟当前三名对手，优先选择第一名达到门槛的对手；无人达标时选择预测胜率最高者，并实际消耗一次挑战。兜底选择仍标为未达标，不会修改设置的门槛。

## 日常使用

- 己方编成未变化时，使用“每日挑战 → 胜率选敌”或单次挑战任务即可；兼容缓存存在时只读取当前三个对手，不重读己方，也不单独识别 Grade。
- “每日挑战 → 胜率选敌”的“竞技场等级（Grade）”默认显示“未识别”，选项随后按 7～1 倒序排列。“未识别”会清除人工覆盖并采用缓存中已识别的 Grade；缓存也没有 Grade 时才会停止。选择 1～7 后，程序会在运行胜率任务时把人工覆盖写回缓存。下拉框不会动态显示缓存值，请以同页只读摘要中的“有效 Grade／来源”为准。
- 当前缓存不会自动识别“用户刚刚改过己方编成”。只要期数或己方编成发生变化，必须由用户手动运行己方重算；也可临时打开“自动重算己方数据”，成功后再关闭。
- 每次真实挑战后游戏会刷新三名对手；未挑战时同一轮对手不会仅因重新打开界面而重排。跨过每日 `04:00` 时流程会停止，重新进入后再运行。
- 本地画面采集默认关闭。只有需要诊断时才选择“仅失败现场”或更高档位；采集数据只保存在当前安装目录的 `.local/runtime-data`，不会自动上传。

## 默认参数

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| 竞技场期数 | 目录最新 | 固定模拟目录中最高的完整期数，可手动选择 |
| 胜率门槛 | 70% | 按考虑抽样波动后的保守下限判断；2000 次通常需约 72.2% 的估计胜率。无人达标时选择预测胜率最高者 |
| 模拟次数 | 2000 | 至少 1000；次数越多通常越慢、估计越稳定。次数越少，达到同一下限门槛所需的估计胜率越高 |
| 模拟超时 | 300 秒（5 分钟） | 一次模拟计算的最长时间，可自行调整；算完立即继续，不是固定等待，也不包含读取游戏画面的时间 |
| 竞技场等级（Grade） | 未识别 | 默认采用己方缓存识别值；可按 7～1 人工覆盖，运行胜率任务时写回缓存 |
| 自动重算己方 | 关闭 | 日常复用缓存，只有首次或编成变化后临时开启 |
| 本地画面采集 | 关闭 | 不保存截图或 ROI；失败时仍保留文字日志 |

模拟次数只影响抽样误差和耗时，不会改变真实胜率。提高胜率任务的次数前，请用相同或更多次数重算己方数据。增加次数或设备较慢时，可调高模拟超时；超过上限会停止本次任务。

新设备首次运行会自动选择适合的并行数量并保存结果，后续直接复用，无需手动试跑或设置核心数。

本地安装迁移会核对旧版界面的默认值：只有从默认 180 秒的版本更新到默认 300 秒时，才将已保存的 180 秒同步改为 300 秒；900、1800 等其他自定义值保留。自由输入框无法区分此前手填的 180 和自动保存的旧默认，这两种情况都会迁移。更新后仍可自行填写 180 秒，后续默认同为 300 秒的更新不会重复覆盖。缺少旧版界面时不推测迁移。

## 先了解再挑战

完整读取三个对手可能需要数分钟；包含自定义强化越多，必须打开的卡片详情越多。期间游戏界面会由 Maa 操作。遇到已支持的临时读取或页面故障，客户端会在固定次数和时限内恢复；仍无法确认输入、模拟或结果时才停止。无需手工接着点击，也不要用连续重试绕过未解决的错误。

继续阅读[竞技场胜率功能](ARENA_WIN_RATE.md)；遇到问题按[故障排查](TROUBLESHOOTING.md)处理。
