# 首次使用

## 适用范围

当前公开预览包面向 Windows x86_64 与 DMM 版游戏窗口。上游 MaaGakumasu 的其他平台和模拟器能力仍属于上游范围；本派生版的竞技场新增能力尚未宣称完成这些环境的等价验证。

竞技场截图须为竖向 `9:16`，短边至少 `720` 像素。MaaFramework 整数缩放造成的长边 1 像素舍入可接受；低于最小门槛会失败关闭。

## 下载与安装

1. 打开 [GitHub Releases](https://github.com/Kirinigh/Gakumas_Helper/releases)，下载当前 Windows x86_64 完整 ZIP。首次安装、从旧组合版本迁移，以及 Release Notes 仍标明“人工迁移预览”的版本都须手动解压并保持 MFA 默认 Stable；只有后续发布预检明确宣布自动升级恢复时，才使用 MFA 内置 GitHub 资源更新。
2. Release 同时提供 checksums。需要人工复核首次下载时，可在 PowerShell 中核对 SHA-256：

   ```powershell
   Get-FileHash "MaaGakumasu-win-x86_64-vXXX.zip" -Algorithm SHA256
   ```

   请把 `vXXX` 替换为实际下载资产中的完整版本号。

3. 手动安装时将 ZIP 解压到一个新的目录。不要把单个文件手工覆盖进上游 Maa、其他派生版或旧版 Gakumas Helper；自动升级恢复后的完整包更新再交给 MFA 内置入口。
4. 运行版本内 `deployment\Start-MaaGakumasu-Admin.cmd`，通过管理员入口启动 Maa。该入口会为 Maa/Agent 子进程设置唯一且初始为空的 TEMP/TMP；直接双击 `MaaGakumasu.exe` 会绕过这项运行环境隔离。非管理员输入端不能控制管理员游戏窗口，程序会在开始任务或挑战前停止。
5. 在 Maa 中按上游方式连接游戏。程序只通过截图、图像识别、光学字符识别 (Optical Character Recognition, OCR) 和正常界面输入工作，不读取游戏进程内存，也不处理 DMM 账号密码。

DMM 用户首次打开时先把控制器从默认“模拟器”改为“PC”，再把资源切换为“DMM”。切换前 MFA 可能针对默认模拟器执行一次连接探针，并在没有 Android 调试桥 (Android Debug Bridge, ADB) 序列号时记录空地址诊断；这不表示“一键日常”业务任务已经执行，也不会连接 DMM 游戏。

## 第一次竞技场运行

1. 确认游戏已登录并停在可进入 `コンテスト` 的主界面，关闭遮挡弹窗。
2. 在 Maa 任务列表中添加“重算竞技场己方总分”。它默认不进入一键预设。
3. 竞技场期数默认选择“目录最新”。如果游戏当前期数与目录默认不一致，请人工选择正确期数；不存在或三个舞台数据不完整时流程会停止。
4. 保持默认 `2000` 次模拟与 `180` 秒模拟超时，单独运行己方重算。它会进入 `リハーサル`，读取三个舞台的当前编成并生成本机缓存，不会发起挑战。
5. 任务成功后，切换到其他任务再返回设置页，核对期数、三个舞台 ID、支援加成、有效 Grade 及来源、九名成员的整数模拟平均值和模拟次数。没有有效缓存的项目显示“未识别”。
6. 添加“竞技场胜率分析并挑战（单次）”。此任务会读取当前三名对手；只有完整模拟且至少一名对手通过安全门槛时，才会选择并实际消耗一次挑战。

## 日常使用

- 己方编成未变化时，使用“每日挑战 → 胜率选敌”或单次挑战任务即可；兼容缓存存在时只读取当前三个对手，不重读己方，也不单独识别 Grade。
- “每日挑战 → 胜率选敌”的“竞技场 Grade”默认显示“未识别”，选项随后按 7～1 倒序排列。“未识别”会清除人工覆盖并采用缓存中已识别的 Grade；缓存也没有 Grade 时才会停止。选择 1～7 后，程序会在运行胜率任务时把人工覆盖写回缓存。下拉框不会动态显示缓存值，请以同页只读摘要中的“有效 Grade／来源”为准。
- 当前缓存不会自动识别“用户刚刚改过己方编成”。只要期数或己方编成发生变化，必须由用户手动运行己方重算；也可临时打开“自动重算己方数据”，成功后再关闭。
- 每次真实挑战后游戏会刷新三名对手；未挑战时同一轮对手不会仅因重新打开界面而重排。跨过每日 `04:00` 时流程会停止，重新进入后再运行。
- 本地画面采集默认关闭。只有需要诊断时才选择“仅失败现场”或更高档位；采集数据只保存在当前安装目录的 `.local/runtime-data`，不会自动上传。

## 默认参数

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| 竞技场期数 | 目录最新 | 固定模拟目录中最高的完整期数，可手动选择 |
| 胜率门槛 | 70% | 三名对手家族校正后的单侧 Wilson 下限必须达到此值 |
| 模拟次数 | 2000 | 每名成员的经验分布样本量；必须至少 1000 |
| 模拟超时 | 180 秒 | 仅约束本地模拟器，不等于整个 UI 读取时长 |
| 竞技场 Grade | 未识别 | 默认采用己方缓存识别值；可按 7～1 人工覆盖，运行胜率任务时写回缓存 |
| 自动重算己方 | 关闭 | 日常复用缓存，只有首次或编成变化后临时开启 |
| 本地画面采集 | 关闭 | 不保存截图或 ROI；失败时仍保留文字日志 |

首次 Worker 自动校准会测试可用并行度并缓存结果。选择逻辑同时考虑耗时和额外核心负载，不单纯选择测得最快的最大 Worker 数。

## 先了解再挑战

完整读取三个对手可能需要数分钟；包含自定义强化越多，必须打开的卡片详情越多。期间游戏界面会由 Maa 操作。没有达标对手、输入不完整、模拟失败或页面状态变化都属于安全停止，不应通过手工抢点或连续重试绕过。

继续阅读[竞技场胜率功能](ARENA_WIN_RATE.md)；遇到问题按[故障排查](TROUBLESHOOTING.md)处理。
