# 故障排查

先记录 Maa 前台的完整提示和错误码。竞技场路线对可恢复读取最多补做一次；继续失败时停止是预期安全行为，不要用手工抢点、反复运行或删除状态文件绕过。

## 常见情况

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 找不到两个新任务 | 启动了上游包，或旧目录被上游更新覆盖 | 检查版本是否带 `+gkh`；从本项目 Release 重新解压到独立目录；在“一键日常”任务列表用“添加任务”加入新入口 |
| Maa 在连接或任务开始时报权限错误 | Maa 输入进程不是管理员，或完整性级别低于游戏 | 关闭 Maa 后以管理员身份重新启动；不要改用非管理员辅助输入工具 |
| `unsupported_capture_resolution` | 截图短边低于 720，长边偏差超过允许的 1 像素舍入，或不是竖向 9:16 | 将游戏画面设为 720×1280 或更高的 9:16 分辨率；540×960 不支持 |
| 提示先重算己方 | 没有缓存，或期数/舞台/引擎/seed/样本数不兼容 | 选择正确期数，单独运行“重算竞技场己方总分” |
| 改了己方编成但没有自动重读 | 缓存不检测用户的编成修改 | 手动重算；不要依赖缓存兼容检查发现编成变化 |
| 选择“目录最新”后停止 | 固定目录没有该期，或三个舞台数据不完整 | 人工选择游戏当前期数；若仍失败，按反馈指南提交目录/版本问题 |
| `p_item_...` | P 道具槽不完整、候选不唯一或详情无法确认 | 不降低阈值；确认无遮挡和分辨率，必要时启用“仅失败现场”复现一次后反馈 |
| `skill_card_...` | 卡排不稳定、身份/重复/强化详情不能唯一闭合 | 确认页面无遮挡并停止重试；记录舞台/成员/槽位和错误码后反馈 |
| `support_bonus...` | 右上角信息层未稳定打开或百分比 OCR 不完整 | 关闭遮挡，确认游戏仍在成员详情；重新运行一次，仍失败则反馈 |
| `arena_grade...` 或 `member_...` | Grade/栏位结构与预期不符，或界面处于过渡帧 | 返回竞技场主界面、等待画面稳定后重试一次 |
| 对手列表为空 | 当日竞技场次数已耗尽 | 等下一竞技场日刷新；不要把 `リハーサル` 页面当作对手页 |
| 跨过 `04:00` 后停止 | 竞技场日可能变化，对手和次数快照失效 | 重新进入竞技场并从头运行本次任务 |
| “没有对手达到安全门槛” | 三名对手的家族校正下限均低于设置值 | 这是正常结果，不消耗挑战；根据前台展示审慎决定是否人工调整门槛 |
| `timeout...` 或模拟器失败 | 本地模拟超过超时、引擎异常或样本设置不匹配 | 保留 180 秒默认值先复现；若增大模拟次数，同步增大超时并重算己方缓存 |
| 完整流程耗时数分钟 | 27 人 UI 读取与必要详情点击是主要耗时 | 观察日志是否持续推进；模拟超时不包含 UI 读取，不要把正常分钟级读取误判为死锁 |
| 挑战后阻止下一轮 | 结果页没有完整记录，总体胜负与三场成绩无法闭合 | 不删除 `.local/arena-win-rate` 中的待决记录；记录是否已消耗次数和前台错误后提交 Issue |
| 自动更新没有切入本派生版 | 当前版本与上游 v1.4.8 具有相同 SemVer 优先级 | 首次必须手动解压安装；见[更新与回滚](UPDATE_AND_ROLLBACK.md) |

## 前台错误分类

当前版本会区分截图分辨率、失败恢复、P 道具、技能卡、竞技场 Grade、演习页面、对手、成员栏位、表现力、支援加成、Maa 操作和超时。请在 Issue 中保留错误码与完整一句提示；底层长详情只需提供同一时段的脱敏摘录。

## 最小复现顺序

1. 记录派生版本、任务入口、竞技场期数、分辨率、模拟参数和是否管理员启动。
2. 返回游戏主界面，关闭弹窗；不要改动己方编成或对手顺序。
3. 对“读取失败”只复现一次。默认保持本地画面采集关闭；如果维护者需要，可改为“仅失败现场”再复现一次。
4. 记录失败发生在点击开始之前还是之后、是否消耗挑战次数、前台错误码和大致时间。
5. 按[问题反馈与分流](../SUPPORT.md)提交。GitHub Issue 是公开页面，先按[隐私与安全](PRIVACY_AND_SAFETY.md)脱敏。

## 不要做

- 不要上传完整 `config`、`appsettings.json`、`.local` 或日志压缩包；
- 不要上传未打码账号、游戏截图、ROI、己方/对手缓存或训练样本；
- 不要关闭 UAC、Defender 或识别安全门；
- 不要手工删除待决挑战记录后继续消耗次数；
- 不要把失败关闭当作成功选敌，也不要用综合力自行填补缺失分数。
