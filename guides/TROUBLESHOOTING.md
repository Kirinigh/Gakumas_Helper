# 故障排查

先记录 Maa 前台的完整提示和错误码。竞技场路线会按故障类型在固定次数和时限内自动恢复，成功后继续；仍失败时保留现场并停止，不要用手工抢点、反复运行或删除状态文件绕过。

## 常见情况

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 找不到两个新任务 | 启动了上游包，或使用了不是本项目的更新通道 | 对照本项目 Release 核对独立 GKH 版本与 GitHub 更新源；不要再用旧版 `+gkh` 后缀判断产品身份。若当前客户端已无法更新，从本项目 Release 手动恢复一个完整版本；在“一键日常”任务列表用“添加任务”加入新入口 |
| DMM 用户首启日志出现空 `AdbSerial` | MFA 首次默认选择“模拟器”，但本机没有 Android 调试桥 (Android Debug Bridge, ADB) 目标 | 这是默认控制器的连接探针，不是“一键日常”业务任务；在界面选择“PC”控制器和“DMM”资源后再连接 |
| Maa 在连接或任务开始时报权限错误 | Maa 输入进程不是管理员，或完整性级别低于游戏 | 关闭 Maa 后通过稳定根管理员入口或版本内 `deployment\Start-MaaGakumasu-Admin.cmd` 重新启动；不要改用非管理员辅助输入工具 |
| `unsupported_capture_resolution` | MaaFramework 返回图像的短边低于 720，长边偏差超过允许的 1 像素舍入，或不是竖向 9:16；该尺寸不一定等于物理窗口尺寸 | 建议使用 720×1280 或更高的 9:16 游戏画面；物理 540×960 已有读取验证，尚未完成完整日常流程验收 |
| 提示先重算己方 | 没有缓存，或期数/舞台/引擎/seed/样本数不兼容 | 选择正确期数，单独运行“重算竞技场己方总分” |
| 改了己方编成但没有自动重读 | 缓存不检测用户的编成修改 | 手动重算；不要依赖缓存兼容检查发现编成变化 |
| 选择“目录最新”后停止 | 已知 RIS production 目录出现更高期数，但新 engine/data 候选无法完整激活，或三个舞台数据不完整 | 保留停止，不要把旧期当作最新；网络恢复后重试，仍失败则按反馈指南提交组件 SHA、目录和版本问题 |
| `p_item_...` | P 道具槽不完整、候选不唯一或详情无法确认 | 不降低阈值；确认无遮挡和分辨率，必要时启用“仅失败现场”复现一次后反馈 |
| `skill_card_...` | 卡排不稳定、身份/重复/强化详情不能唯一闭合 | 确认页面无遮挡并停止重试；记录舞台/成员/槽位和错误码后反馈 |
| `support_bonus...` | 右上角信息层未稳定打开或百分比 OCR 不完整 | 关闭遮挡，确认游戏仍在成员详情；重新运行一次，仍失败则反馈 |
| `arena_grade...` 或 `member_...` | Grade/栏位结构与预期不符，或界面处于过渡帧 | 返回竞技场主界面、等待画面稳定后重试一次 |
| 对手列表为空 | 当日竞技场次数已耗尽 | 等下一竞技场日刷新；不要把 `リハーサル` 页面当作对手页 |
| 跨过 `04:00` 后停止 | 竞技场日可能变化，对手和次数快照失效 | 重新进入竞技场并从头运行本次任务 |
| 没有对手达到门槛但仍发起挑战 | 三名对手的家族校正下限均低于设置值 | 程序按预测胜率最高者兜底选择并消耗一次挑战；记录仍为未达标，设置的门槛保持不变 |
| `timeout...` 或模拟器失败 | 本地模拟超过超时、引擎异常或样本设置不匹配 | 保留 180 秒默认值先复现；若增大模拟次数，同步增大超时并重算己方缓存 |
| 完整流程耗时数分钟 | 27 人 UI 读取与必要详情点击是主要耗时 | 观察日志是否持续推进；模拟超时不包含 UI 读取，不要把正常分钟级读取误判为死锁 |
| 挑战后阻止下一轮 | 有界恢复后仍未确认三个舞台赢家、总体胜负或回场；分数异常本身不会阻断 | 不删除 `.local/arena-win-rate` 中的待决记录；记录是否已消耗次数和前台错误后提交 Issue |
| 自动更新没有找到当前 Latest | 旧安装仍使用上游更新源、处于旧组合版本命名空间，或更新检查失败 | 当前版本为非预发布 Latest；独立 GKH 版本保持默认 Stable 并核对本项目 GitHub 更新源。旧组合版本迁移或更新入口不可用时，手动安装 Latest 完整包，见[更新与回滚](UPDATE_AND_ROLLBACK.md) |
| 内置更新下载或应用失败 | 网络、Release 资产或 MFA 文件事务失败 | 保留当前版本与提示，不手工混入单个 Agent、模型、UI 或数据文件；重试网络后仍失败则按[更新与回滚](UPDATE_AND_ROLLBACK.md)恢复上一完整版本 |

## 前台错误分类

当前版本会区分截图分辨率、失败恢复、P 道具、技能卡、竞技场 Grade、演习页面、对手、成员栏位、表现力、支援加成、Maa 操作和超时。请在 Issue 中保留错误码与完整一句提示；底层长详情只需提供同一时段的脱敏摘录。

## 最小复现顺序

1. 记录派生版本、任务入口、竞技场期数、分辨率、模拟参数和是否管理员启动。
2. 返回游戏主界面，关闭弹窗；不要改动己方编成或对手顺序。
3. 对“读取失败”只复现一次。默认保持本地画面采集关闭；如果维护者需要，可改为“仅失败现场”再复现一次。
4. 记录失败发生在点击开始之前还是之后、是否消耗挑战次数、前台错误码和大致时间。
5. 按[问题反馈与分流](../SUPPORT.md)提交。GitHub Issue 是公开页面，先按[隐私与安全](PRIVACY_AND_SAFETY.md)脱敏。

## 不要做

- 不要上传完整 `config`、`appsettings.json`、`.local` 或日志压缩包；
- 不要上传未打码账号、游戏截图、ROI、己方/对手缓存或训练样本；
- 不要关闭 UAC、Defender 或识别安全门；
- 不要手工删除待决挑战记录后继续消耗次数；
- 不要把失败关闭当作成功选敌，也不要用综合力自行填补缺失分数。
